## 1. Incident Summary

**Title:** Unauthorised Access to Client Portfolio Data via Compromised API Key

On 8 May 2026, the security team identified that a valid API key with read access to the client portfolio management system had been exposed in a public GitHub repository by a junior developer. Log analysis confirmed that an external IP address used the key to query portfolio data for approximately 1,800 client accounts over a 12-day period before detection. Extracted data included client names, account numbers, portfolio holdings, and valuations.

## 2. Detection

**Detection Method:** GitHub secret scanning alert (external service) flagged the exposed API key; cross-referenced with API gateway logs showing unusual query patterns from an unrecognized IP.

**Detection Timestamp:** 2026-05-08T09:15:00+02:00

## 6. Root Cause Analysis

A junior developer committed production API credentials to a personal (public) GitHub repository while working on a proof-of-concept integration. The API key had overly broad read permissions due to inadequate key scoping during provisioning. No automated secret scanning was in place for the internal codebase prior to this incident.

## 7. Remediation Actions

Revoked compromised API key; implemented automated secret scanning on all repositories; enforced API key scoping to minimum required permissions; mandatory security training for all development staff; reviewed all active API keys for over-permissioning.
