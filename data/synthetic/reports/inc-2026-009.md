## 1. Incident Summary

**Title:** Firewall Misconfiguration Exposes Internal API to Public Internet

On 28 March 2026, a routine external vulnerability scan identified that an internal fund administration API endpoint was inadvertently exposed to the public internet following a firewall rule change on 20 March. The API required authentication and no unauthorized access was detected in the 8-day exposure window. However, the endpoint's existence and authentication scheme were visible to external scanners.

## 2. Detection

**Detection Method:** Quarterly external vulnerability scan by third-party penetration testing firm.

**Detection Timestamp:** 2026-03-28T11:00:00+01:00

## 3. Timeline


- 20 March 2026: Network team applies firewall rule change for new VPN configuration; inadvertently opens port 8443 to public
- 28 March 2026, 11:00 CET: Vulnerability scan report flags externally reachable internal API
- 11:30 CET: Network team confirms misconfiguration; closes port immediately
- 12:00 CET: Log review initiated for 8-day exposure window
- 14:00 CET: Log review confirms no unauthorized access attempts against the API
- 15:00 CET: Change management review initiated

## 4. Affected Systems

## 6. Root Cause Analysis

Firewall rule change request did not go through the standard four-eyes change approval process due to being tagged as 'low-risk VPN maintenance'. The rule inadvertently allowed inbound traffic on port 8443 from any source instead of VPN subnet only.

## 7. Remediation Actions

Port closed; firewall rules audited; change management process updated to require security team approval for all firewall changes regardless of risk classification.
