## 1. Incident Summary

**Title:** Database Corruption During Scheduled Maintenance Window

On 10 February 2026, a database schema migration performed during a scheduled maintenance window resulted in corruption of the trade settlement records table. Approximately 4,200 settlement records from the previous 48 hours became inconsistent. The settlement processing system was taken offline for 5 hours while data was restored from backups and reconciled. 78 institutional investors with pending settlements were affected across Luxembourg and Germany.

## 2. Detection

**Detection Method:** Post-migration validation script detected data inconsistencies; operations team escalated immediately.

**Detection Timestamp:** 2026-02-10T03:00:00+01:00

## 6. Root Cause Analysis

Database migration script contained an incorrect foreign key constraint that cascaded a NULL value across 4,200 records. The migration was tested on a staging environment with a subset of data that did not contain the edge case triggering the corruption.

## 7. Remediation Actions

Restored from backup; implemented mandatory full-dataset migration testing policy; added pre-migration snapshot requirement; migration rollback procedure documented and rehearsed.
